# Έντυπα — πρόχειρα (autosave + «Πρόχειρα»)

Ένα μισοσυμπληρωμένο έντυπο δεν χάνεται πια: τηλεφώνημα στη μέση, άλλη
φόρμα, κλειδωμένο iPad — ό,τι έχει πληκτρολογηθεί επιβιώνει. Όλη η
λογική ζει στο [../forms/_drafts.fw.js](../forms/_drafts.fw.js)· κάθε
σελίδα δηλώνει έναν μικρό adapter (`FWDrafts.register`) γιατί οι φόρμες
έχουν τρεις διαφορετικές αρχιτεκτονικές (DOM `data-k` στα τρία
υπογεγραμμένα, `state` object στην καταχώριση, `$("id").value` σε
προσφορά/εκτίμηση).

## Το μοντέλο

- **Ένα πρόχειρο = μία επίσκεψη που προχώρησε.** Πρόχειρο γεννιέται όταν
  έχει συμπληρωθεί το **10% των πεδίων** της φόρμας, και ποτέ με
  λιγότερα από **3**: ένα tap σε ένα segment ή σε έναν διακόπτη δεν
  γεμίζει τα «Πρόχειρα» με άδεια έντυπα. Πρακτικά το κατώφλι είναι 3
  πεδία παντού, 4 στην εκτίμηση (35 πεδία). Επιλεγμένο ακίνητο ή επαφή
  από το CRM μετράει για δύο, γιατί είναι αναζήτηση και όχι πάτημα.
  Μόλις υπάρξει πρόχειρο, κάθε επόμενη αλλαγή ενημερώνει *αυτό*, ακόμα
  κι αν σβήσεις πεδία (debounce 900 ms + σύγχρονο flush σε
  `pagehide`/κλείδωμα). Προεπιλογές (π.χ. η σημερινή ημερομηνία) δεν
  μετράνε — συγκρίνονται με baseline snapshot της φρέσκιας φόρμας.
- **Το έντυπο ανοίγει πάντα κενό.** Αν υπάρχουν πρόχειρα, ένα μπάνερ
  πάνω από τη φόρμα τα λιστάρει («Συνέχεια» / «×»)· τίποτα δεν
  φορτώνει και τίποτα δεν σβήνεται χωρίς tap. Η αρχική (`index.html`)
  δείχνει ενότητα «ΠΡΟΧΕΙΡΑ» για όλα τα έντυπα μαζί, με deep link
  `σελίδα.html?draft=<id>`.
- **Επιτυχής υποβολή (ή είσοδος στο outbox) διαγράφει το πρόχειρο** —
  το payload είναι πια ασφαλές στο [_outbox.fw.js](../forms/_outbox.fw.js).
  Λήξη στις **30 ημέρες**, μέγιστο **10 ανά έντυπο** (φεύγει το
  παλιότερο).

## Υπογραφές: σκόπιμα ΔΕΝ σώζονται

Η υπογραφή δένει με το ακριβές κείμενο που είδε ο πελάτης εκείνη τη
στιγμή. Πρόχειρο που αλλάζει μετά (ποσό, διάρκεια, ακίνητο) με
«κρατημένη» υπογραφή θα κατασκεύαζε υπογεγραμμένο έγγραφο που δεν
υπογράφτηκε ποτέ. Μετά από ανάκτηση, υπογράφουν ξανά και οι δύο.

## Αποθήκευση

`localStorage` κλειδί `fw_drafts_v1`, σχήμα
`{ [form]: [{id, label, created_at, updated_at, v}] }`. Χωρίς
υπογραφές/PDF τα πρόχειρα είναι μικρό JSON, και το σύγχρονο API
επιτρέπει αξιόπιστο flush στο `pagehide` (το IndexedDB δεν προλαβαίνει).
Στην εγκατεστημένη Home-Screen εφαρμογή το storage εξαιρείται από το
7-day eviction του Safari — ίδιο σκεπτικό με το outbox. Η προσφορά και
η εκτίμηση σώζουν και το επιλεγμένο ακίνητο/επαφή **ως raw record** του
CRM, όχι ξανά lookup. Το παλιό μονό πρόχειρο της καταχώρισης
(`fw_draft_kx2`) μεταφέρεται μία φορά στη νέα αποθήκη στο πρώτο άνοιγμα.

## Πώς κουμπώνει μια νέα φόρμα

```js
FWDrafts.register({
  form: "…",            // το CONFIG.id / form string του payload
  mount: "#step1",       // πού μπαίνει το μπάνερ + το status line
  collect: () => {...},  // τρέχουσες τιμές (plain object, χωρίς υπογραφές)
  apply: v => {...},     // επαναφορά τιμών ΚΑΙ του UI (segs, toggles, pickers)
  label: v => "…",       // ετικέτα για τις λίστες (όνομα — διεύθυνση)
  onSave: msg => {...},  // προαιρετικό: δικό της saved-tag (καταχώριση)
});
```

Μετά από επιτυχή υποβολή: `FWDrafts.discard()`. Μετά από reset της
φόρμας (π.χ. «Νέα προσφορά»): `FWDrafts.rebase()` — αλλιώς το autosave
θα έσωζε το άδειασμα ως πρόχειρο. Σελίδες που αλλάζουν state χωρίς
DOM events (η καταχώριση) καλούν `FWDrafts.touch()`.

Νέο αρχείο στο shell → μπήκε στο `SHELL` του
[../forms/sw.js](../forms/sw.js) (bump `VERSION` σε κάθε αλλαγή εδώ).
